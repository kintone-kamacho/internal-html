🔒 リポジトリのPrivate化
✅
対応済み（2026-05-01） 既にPrivateに変更済みです。再度変更が必要な場合のみ以下の手順を使用してください。
1

Settingsを開く

リポジトリページ上部の「Settings」タブをクリック

2

Danger Zoneまでスクロール

ページ最下部の赤い枠「Danger Zone」セクションまでスクロール

3

「Change repository visibility」をクリック

「Change to private」を選択し、確認ダイアログで操作を完了する

👤 メンバーの追加・削除

メンバーを追加する

1

Manage accessを開く

Settings → Collaborators → Manage access

2

「Add people」をクリック

相手のGitHubユーザー名またはメールアドレスを入力して検索

3

権限を選択して招待

通常は「Write」で十分。招待メールが相手に届くので、承認してもらう。

4

相手に連絡する

GitHubに登録しているメールに招待が届く。届かない場合は https://github.com/notifications を確認してもらう。

メンバーを削除する

1

Manage accessを開く

Settings → Collaborators → Manage access

2

対象メンバーの「Remove」をクリック

即時アクセス不可になる。相手への通知は自動では届かないので必要に応じて連絡する。

⚠️
招待の有効期限に注意 招待を承認しないまま放置すると一定期間で失効します。未承認のまま時間が経ったら再招待してください。
🌐 GitHub Pages確認・設定
1

Pages設定を確認する

Settings → Pages → 「Your site is published at〜」が表示されていればOK

2

公開URLにアクセスして確認

https://kintone-kamacho.github.io/internal-html/

ℹ️
pushしてから反映まで数分かかる場合がある 編集内容をpushした後、GitHub Pagesへの反映には最大5分程度かかることがあります。
🎖 権限の使い分け
権限 できること 用途
Admin Settings変更・メンバー管理・削除も含む全操作 管理者（自分）
Write ファイルの編集・push・pull 引き継ぎメンバー（通常はこれでOK）
Read 閲覧のみ 参照だけさせたい場合
✅ 新メンバー追加チェックリスト
  • 相手のGitHubアカウントを確認済み
  • Manage access → Add people で招待済み（権限：Write）
  • 相手が招待メールを承認したことを確認
  • マニュアルURL（https://kintone-kamacho.github.io/internal-html/）を共有済み
  • ローカルへのクローン手順をマニュアルで案内済み
🚨 よくあるトラブル
Q

招待メールが届かない

相手に https://github.com/notifications を確認してもらう。それでもなければ一度削除して再招待。

Q

GitHub Pagesが更新されない

pushから最大5分待つ。それでも更新されない場合はActions → Pages buildのログを確認。

Q

メンバーが「pushできない」と言っている

Manage accessで権限が「Write」以上になっているか確認する。

Q

自分がSettingsを操作できなくなった

アカウントの切り替えや別ブラウザでログインし直すと解決することが多い。
