🔄 日常の作業手順・運用ルール

⚠️ 作業を始める前に必ず Fetch / Pull を実行してください。
忘れると他の人の変更と衝突（コンフリクト）が起きる可能性があります。
1

最新版を取得する（Fetch origin → Pull）

GitHub Desktop を開き、まず最新の状態を取得します。

🖥️ GitHub Desktop の操作
  1. GitHub Desktop を起動し、左上でリポジトリが internal-html になっていることを確認
  2. 上部の Fetch origin ボタンをクリック（GitHubの状態を確認）
  3. 「Pull origin」と表示が変わったらクリックして最新版を取得
  4. 「This branch is up to date with origin/main.」と表示されれば最新の状態です
▶ コマンドプロンプトの場合（参考）
C:\source\internal-html> git pull
# Already up to date. と出れば最新版
2

ファイルを編集する

VS Code でHTMLファイルを開き、修正・追加を行います。GitHub Desktop から直接開けます。

🖥️ VS Code を開く手順
  1. GitHub Desktop のメニュー Repository → Open in Visual Studio Code をクリック
  2. または画面中央の Open in Visual Studio Code ボタンをクリック
💡 新しいツールを追加するときは、既存のツールフォルダをコピーして名前を変えると便利です。
追加したら index.html のツール一覧にもリンクを追加してください。
3

変更を記録する（Commit）

ファイルを保存すると、GitHub Desktop の左側に変更されたファイルが一覧表示されます。

🖥️ GitHub Desktop の操作
  1. 左ペインに変更ファイルの一覧が表示される（チェックが入っていることを確認）
  2. 左下の 「Summary (required)」 欄に変更内容を一言で入力する
    　例：QRコード生成ツールのボタンデザインを修正
  3. （任意）「Description」欄に詳細メモを書いてもOK
  4. Commit to main をクリック
💬 コミットメッセージの書き方：
「何をしたか」が一言でわかるように書きます。
✅ 良い例：注文状況ツールに印刷ボタンを追加
❌ 悪い例：修正 / update / 作業
▶ コマンドプロンプトの場合（参考）
C:\source\internal-html> git add .
C:\source\internal-html> git commit -m "変更内容を一言で"
4

GitHubへ送信する（Push）

コミットが完了すると、上部のボタンが変わります。

🖥️ GitHub Desktop の操作
  1. 上部のボタンが Push origin に変わったらクリック
  2. 「Last fetched just now」と表示されたら送信完了
✅ Push が完了したら作業終了です。
他のメンバーが GitHub Desktop で「Fetch → Pull」すると最新版を取得できます。
▶ コマンドプロンプトの場合（参考）
C:\source\internal-html> git push
📏 チームの運用ルール
  • ⬇️作業開始時は必ず Fetch → Pull を実行する。
    他の人が更新している可能性があります。
  • 📝コミットメッセージは日本語で具体的に書く。
    後から見たときに何をしたかわかるようにします。
  • ☁️作業が終わったらその日のうちに Push する。
    ローカルにためすぎると衝突が起きやすくなります。
  • 🚫テスト中・未完成のファイルは Push しない。
    ブラウザで動作確認が取れてから Push してください。
  • 📅ツールのHTMLにはコメントで更新日を記録する。
    ツール一覧（index.html）の「更新日」も合わせて修正してください。
  • 💬大きな変更をするときは事前に声をかける。
    同じファイルを同時に編集すると衝突が起きます。
🆘 よくあるエラーと対処法
❌ 「Push origin」が「Push origin (↑1)」のまま失敗する / エラーダイアログが出る

原因： 自分が Pull してから、他の人が Push しています。GitHubの方が新しい状態です。

対処： まず Fetch → Pull してから再度 Push します。

🖥️ GitHub Desktop の操作
  1. Fetch origin → Pull origin をクリック
  2. その後 Push origin をクリック
❌ 「We found some conflicts」— コンフリクト（衝突）が発生した

原因： 同じファイルの同じ行を2人が別々に編集してしまいました。

対処： GitHub Desktop が衝突箇所を教えてくれます。VS Codeで開いてどちらの変更を残すか選択します。

🖥️ 対処手順
  1. GitHub Desktop に「Resolve conflicts before Merge」と表示されたら 「Open in Visual Studio Code」 をクリック
  2. VS Code でコンフリクト箇所が色分け表示されるので「Accept Current Change」か「Accept Incoming Change」を選ぶ
  3. ファイルを保存して GitHub Desktop に戻る
  4. Commit merge → Push origin をクリック
⚠️ 困ったらVS Codeを閉じずに担当者に声をかけてください。一緒に確認します。
❌ リポジトリが GitHub Desktop に表示されない

原因： まだクローンしていないか、別のPCでの作業です。

対処： 初回セットアップ STEP 2 を参照してクローンを実行してください。

❌ 間違えてコミットしてしまった（Push する前）

原因： 誤った内容をコミットしてしまいました。Push 前であれば簡単に取り消せます。

🖥️ GitHub Desktop の操作
  1. メニュー Edit → Undo Commit をクリック（またはショートカット Ctrl + Z）
  2. コミットが取り消され、変更はそのままの状態に戻ります
🚨 Push済みのコミットは勝手に取り消さないでください。
Push後に間違えた場合は担当者に相談してください。
❌ ログインを求められる / Authentication failed

原因： GitHub へのサインインが切れています。

🖥️ GitHub Desktop の操作
  1. メニュー File → Options を開く
  2. 「Accounts」 タブで GitHub.com のアカウントを確認
  3. サインアウトされていたら 「Sign in」 から再ログイン
🌿 ブランチ運用
💡 ブランチとは？
mainブランチを「本番」として、作業用に別のブランチを作って編集する方法です。
完成したらmainに取り込む（マージする）ことで、作業中の不完全な内容が本番に影響しません。
⚠️ 注意：ブランチを切り替え忘れると今日のような混乱が起きます。
作業前に必ず現在のブランチを確認してください。

1

作業用ブランチを作成する

mainブランチにいる状態で新しいブランチを作ります。ブランチ名は作業内容がわかる名前にしてください。

🖥️ GitHub Desktop の操作
  1. 上部中央のブランチ名が 「main」 になっていることを確認
  2. 「Branch」 メニュー → 「New branch」 をクリック
  3. ブランチ名を入力（例：fix/qr-tool / add/new-tool）
  4. Create branch をクリック
  5. 上部のブランチ名が新しいブランチ名に変わったことを確認
📝 ブランチ名の例：
fix/order-csv（修正系）　add/daily-report（追加系）　update/manual（更新系）
2

編集・コミット・Pushする

通常の作業手順と同じです。ブランチ上で編集・コミット・Pushを行います。

⚠️ 作業前に必ず上部のブランチ名を確認してください。
「main」のままになっていたら作業用ブランチに切り替えてから編集します。
🖥️ GitHub Desktop の操作
  1. 上部のブランチ名が作業用ブランチになっていることを確認
  2. ファイルを編集・保存する
  3. コミットメッセージを入力して Commit to [ブランチ名] をクリック
  4. Push origin をクリック
3

mainにマージする（取り込む）

ブラウザで動作確認が取れたら、mainブランチに取り込みます。

🖥️ GitHub Desktop の操作
  1. 上部のブランチを 「main」 に切り替える
  2. 「Branch」 メニュー → 「Merge into current branch」 をクリック
  3. 作業用ブランチを選択する
  4. Create a merge commit をクリック
  5. Push origin をクリック
✅ Push が完了したら GitHub Pages に反映されます（数分かかる場合があります）。
4

作業用ブランチを削除する

マージ完了後、作業用ブランチは不要になるので削除してすっきりさせましょう。

🖥️ GitHub Desktop の操作
  1. 作業用ブランチに切り替える
  2. 「Branch」 メニュー → 「Delete」 をクリック
  3. 「Delete branch on remote」にチェックを入れて削除
